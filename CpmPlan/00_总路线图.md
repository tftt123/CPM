# CPM 系统开发总路线图（13阶段）

> 机加工行业 Customer Project Management
> 技术栈：.NET 8 + SQL Server 2022 + Vue 3
> 从零开始，循序渐进

---

## 核心原则

1. **先跑通，再完善** — 每个阶段结束都有一个能点击、能保存、能看的页面
2. **先单表，后关联** — 先做基础CRUD，再加复杂流程
3. **先Mock，后集成** — QAD集成放到后面，前面用假数据
4. **每2周一个里程碑** — 给自己明确的deadline

---

## 技术栈（已确定）

- **前端**：Vue 3 + TypeScript + Element Plus + Vite
- **后端**：.NET 8 Web API + EF Core 8 + JWT + Hangfire
- **数据库**：SQL Server 2022（或 2019）
- **缓存**：Redis
- **工作流**：自研状态机（P1-P9）→ 后期可选 Workflow Core
- **实时推送**：SignalR（看板实时刷新）
- **定时任务**：Hangfire（预警扫描、QAD同步）
- **部署**：IIS 或 Windows Service（传统制造业常用）

## 各阶段详细说明

### P0 环境搭建（3天）

目标：所有工具安装好，前后端能联通。

- [ ] 安装 .NET 8 SDK
- [ ] 安装 SQL Server 2022 Developer + SSMS
- [ ] 安装 Node.js 20 LTS
- [ ] 安装 Visual Studio 2022 Community（.NET桌面开发 + ASP.NET）
- [ ] 安装 VS Code
- [ ] 安装 Redis（Windows版）
- [ ] 创建 ASP.NET Core Web API 项目
- [ ] 创建 Vue3 项目
- [ ] 写一个测试接口：前端点击按钮，后端返回"Hello CPM"
- [ ] 解决跨域问题

**验收标准**：浏览器访问前端页面，点击按钮弹出"Hello CPM"。

---

### P1 用户登录（5天）

目标：系统有门，不同的人看到不同的菜单。

- [ ] 后端：用户表、角色表、权限表（RBAC）
- [ ] 后端：ASP.NET Core JWT认证（Bearer Token）
- [ ] 后端：密码加密存储（BCrypt.Net）
- [ ] 前端：登录页（Element Plus Form）
- [ ] 前端：Vue Router路由守卫（未登录跳转登录页）
- [ ] 前端：侧边栏菜单根据角色动态显示

**验收标准**：
- 销售账号登录看到【报价】【样品】【看板】
- 技术账号登录看到【批次评审】【生产计划】
- 采购账号登录看到【采购管理】

---

### P2 基础数据（5天）

目标：把客户、产品、供应商信息录入系统。

- [ ] 客户管理：增删改查，字段（客户编码、名称、行业、联系人）
- [ ] 产品管理：增删改查，字段（产品编码、名称、材质、表面处理）
- [ ] 供应商管理：增删改查
- [ ] 所有页面：表格 + 分页 + 搜索框
- [ ] 数据校验：必填项、编码唯一性

**验收标准**：能录入50个客户、100个产品，搜索能准确定位。

---

### P3 报价流程（10天）

目标：实现第一个核心业务流程——从商机到报价。

- [ ] 商机表：客户、预计金额、阶段、截止日期
- [ ] 报价单表：关联商机、产品、数量、单价
- [ ] 技术评审：技术负责人填写可行性和成本
- [ ] 定价审批：销售主管审批（同意/退回）
- [ ] 审批状态流转：草稿→待评审→待审批→已报价→赢单/输单
- [ ] 前端：商机列表页、详情页、审批操作按钮

**验收标准**：
- 销售创建商机 → 技术收到待办 → 技术评审 → 主管审批 → 发出报价
- 审批人能看到自己待办的任务列表

---

### P4 样品申请（7天）

目标：赢单的商机可以发起样品制作。

- [ ] 样品申请单：关联商机、需求数量、截止日期、技术要求
- [ ] 文件上传：上传图纸/规格书（存本地/IIS虚拟目录）
- [ ] 主管审批：样品申请提交后主管审批
- [ ] 审批通过后：通知技术部门负责人
- [ ] 前端：样品申请页、审批页、文件预览

**验收标准**：销售发起样品申请 → 上传图纸 → 主管批准 → 技术收到通知。

---

### P5 批次管理（7天）

目标：技术部门拆分批次并制定计划。

- [ ] 批次表：关联样品申请、批次号、计划数量、计划起止日期
- [ ] 批次拆分：一个样品申请拆分为多个批次
- [ ] 生产计划：填写每批次的生产日期和节拍
- [ ] 超期检查：计划完成日 > 客户截止日 标红
- [ ] 状态：待排产→计划中→生产中→已完成

**验收标准**：
- 一个需求500个的样品，拆成A01(200个)、A02(300个)
- 计划日期超过截止日期的批次自动标红

---

### P6 采购管理（7天）

目标：样品原材料的采购跟踪。

- [ ] 采购申请：技术人员填写物料清单
- [ ] 采购主管审批
- [ ] 采购订单：供应商、数量、计划到货日
- [ ] 到货验收：合格/数量不足/品质不合格
- [ ] 采购状态：无需采购/待申请/采购中/已到货/异常
- [ ] 批次与采购关联：采购完成才能排产

**验收标准**：
- 采购中的批次显示"采购中"
- 采购到货后批次状态变为"可排产"

---

### P7 看板V1（5天）

目标：一屏看全所有样品进展。

- [ ] 看板表（宽表）：项目、客户、产品、批次、计划日期、实际日期、状态
- [ ] 看板页面：按状态分栏（已完成/生产中/超期预警/数量超出）
- [ ] 筛选器：我的项目/本月截止/超期预警
- [ ] 实时更新：SignalR推送状态变更

**验收标准**：销售打开看板，不用问技术就知道每个批次的进展。

---

### P8 催产变更（5天）

目标：计划不满足时走系统化的催产流程。

- [ ] 催产申请表：关联批次、客户诉求、期望日期、紧急程度
- [ ] 技术主管审批：同意（更新计划日期）/拒绝（说明原因）
- [ ] 催产通过后：自动更新批次计划日期，看板刷新
- [ ] 催产拒绝后：销售可选择更新客户截止日

**验收标准**：销售发起催产 → 技术主管批准 → 看板日期自动更新。

---

### P9 交付送样（5天）

目标：完成样品交付闭环。

- [ ] 交付单：实际完成数量、实际日期、质检结果
- [ ] 超量预警：实际数量 > 计划数量 自动通知销售
- [ ] 送样单：送样日期、地址、快递单号、费用承担
- [ ] 客户反馈：认可/需修改/不认可
- [ ] 需修改时：重新发起样品申请

**验收标准**：
- 技术提交交付单 → 实际数量120超过计划100 → 销售收到通知
- 销售创建送样单 → 客户确认认可 → 进入合同谈判

---

### P10 QAD集成（7天）

目标：对接QAD 2016EE，打通库存数据。

- [ ] 集成配置：QAD连接参数（ODBC/Progress OpenEdge驱动）
- [ ] 产品同步：从QAD同步产品主数据到CPM
- [ ] 库存查询：对接QAD库存判断是否需采购
- [ ] 定时同步：Hangfire Job每15分钟同步一次库存
- [ ] 对接方式：ODBC只读同步到MSSQL中间表

**验收标准**：样品申请时，系统自动显示QAD实时库存。

---

### P11 预警通知（5天）

目标：系统自动提醒，不用人盯。

- [ ] 预警规则：技术评审超24h、审批超8h、截止前3天/1天
- [ ] 定时扫描：Hangfire Recurring Job每分钟扫描超时任务
- [ ] 通知方式：站内信（必做）+ 邮件（选做）
- [ ] 通知中心：右上角铃铛图标，显示未读通知
- [ ] 看板联动：超期批次在看板上红色闪烁

**验收标准**：创建一个超24h未审批的报价，系统主动推送通知。

---

### P12 上线准备（7天）

目标：系统能稳定运行在生产环境。

- [ ] 数据导入：Excel模板导入客户/产品/供应商
- [ ] 数据初始化：管理员账号、角色权限配置
- [ ] 测试：每个核心流程走通至少3次
- [ ] IIS部署：前端dist目录 + 后端Web API站点
- [ ] SQL Server备份计划：每日自动备份
- [ ] 发布配置：appsettings.Production.json

**验收标准**：
- 服务器上浏览器能访问系统
- 销售、技术、采购各角色能完成各自工作

## 新手避坑指南

### 1. 不要追求完美
- 第一阶段用最简单的表单和表格，不要加花哨动画
- 文件上传先用IIS虚拟目录存本地，后面再换MinIO/OSS
- 搜索先用EF Core的Contains，后面再加全文检索

### 2. 先保证数据能存能查
- 每个功能先做：列表页 → 新增页 → 编辑/删除
- 列表页必须有：分页 + 搜索 + 状态筛选

### 3. 遇到问题先简化
- 审批流复杂？先做个字段status=0/1/2/3模拟流转
- SignalR不会？先定时刷新页面（每30秒）
- Hangfire不会？先用Windows计划任务跑定时Console程序

### 4. 每天提交代码
```bash
git add .
git commit -m "P3-报价流程-完成技术评审功能"
```

## .NET 新手特别提醒

| 容易混淆的点 | 正确做法 |
|-------------|---------|
| `DateTime` vs `DateTimeOffset` | 数据库用`datetime2`，C#用`DateTime`，统一本地时间 |
| EF Core 迁移 | 命令：`Add-Migration InitialCreate` → `Update-Database` |
| JWT配置 | 放在`appsettings.json`，用`IOptions<JwtSettings>`注入 |
| 跨域 | `Program.cs`里加`builder.Services.AddCors()` |
| 文件上传 | 用`IFormFile`，存到`wwwroot/uploads`或配置的路径 |
