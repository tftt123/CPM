# 审批系统配置重构计划

## 需求背景
用户提出6个改进点，旨在让审批系统更灵活、更易维护。

## 需求明细与决策

### 1. ModuleType 可配置化
**现状**：ModuleType 是硬编码字符串，分散在前端 `ApprovalConfig.vue`（`Quotation`/`Sample`/`Procurement`）和后端各处（`QuotationService.cs` 传 `"QUOTATION"`，`QuotationForm.vue` 传 `"quotation"`）。

**目标**：ModuleType 改为数据库可配置项，在系统设置页面维护，审批配置页面下拉框动态加载。

**方案**：
- 新建 `SysModuleTypeConfig` 表（Id, ModuleType[唯一], ModuleName, Description, IsActive, CreatedAt）
- 后端提供 CRUD API
- 前端新增系统设置子页面"业务模块配置"
- 审批配置页面的 ModuleType 下拉框改为从 API 加载
- 预置初始数据：`Quotation`(报价单), `Sample`(样品), `Procurement`(采购), `PmStepCycleTime`(实际节拍维护)

### 2. IsDefault 作用澄清
**现状**：`FindBestTemplateAsync` 中 `IsDefault` 只是排序键（`ThenByDescending(t => t.IsDefault)`）。

**行为**：
1. 先按 `ModuleType + IsActive` 筛选
2. 再按 `Site` 精确匹配（站点专属优先于全局）
3. **同一 ModuleType + Site 下有多个模板时**，`IsDefault=true` 的优先被选中
4. 如果都没有设置 `IsDefault`，则按 `CreatedAt` 取第一个

**结论**：不设置 IsDefault 不会导致模板不生效，只是在多个模板并存时失去优先权。

### 3. 加入实际节拍维护
- 在 `SysModuleTypeConfig` 初始数据中预置 `PmStepCycleTime`
- PM 模块提交审批时传入 `moduleType = "PmStepCycleTime"`

### 4. TemplateCode 自动生成 + 前端隐藏
**现状**：TemplateCode 是用户必填输入框，有数据库唯一索引。

**目标**：创建模板时后端自动生成，前端不再显示和编辑。

**编码规则**：`{ModuleType}-{Timestamp}-{Random}`
- 示例：`Quotation-20260512-143052-A7B3`

**改动**：
- 后端：创建模板时自动生成 TemplateCode，去掉前端传入的校验
- 前端：去掉 TemplateCode 输入框和验证规则
- 数据库：保留唯一索引，但值由后端控制

### 5. 保留 TemplateName 作为描述
- TemplateName 保持 Required，用途改为"模板描述/说明"
- 前端 label 改为"模板描述"

### 6. 统一大小写
**现状三套写法**：
| 位置 | 值 |
|------|-----|
| 审批模板配置 | `Quotation` |
| 审批 service businessType | `Quotation` |
| 审批 service moduleType | `QUOTATION` |
| 文件上传 moduleType | `quotation` |

**统一方案**：
- `businessType` 和 `moduleType`（审批匹配用）：统一为 **PascalCase** `"Quotation"`
- `FileRecord.ModuleType`（文件路径用）：保持 **lowercase** `"quotation"`（文件系统路径惯例）
- 所有后端调用点统一修正

## 实施阶段

### 阶段一：数据库与后端 API
1. 新建 `SysModuleTypeConfig` 实体
2. `CpmDbContext` 注册 DbSet
3. 生成迁移 + 预置种子数据
4. 新建 `ModuleTypeConfigService` + `IModuleTypeConfigService`
5. 新建 `ModuleTypeConfigController`（CRUD，只允许管理员操作）
6. `ApprovalTemplate` 创建逻辑：自动生成 TemplateCode

### 阶段二：后端大小写统一
1. `QuotationService.cs`：所有 `"QUOTATION"` → `"Quotation"`
2. `QuotationController.cs`：所有 `"QUOTATION"` → `"Quotation"`
3. `PmProjectTraceService.cs`：提交审批传入 `"PmStepCycleTime"`

### 阶段三：前端变更
1. 新建 `src/api/moduleTypeConfig.ts`（模块类型配置 API）
2. 新建/集成系统设置页面 `ModuleTypeConfig.vue`
3. `ApprovalConfig.vue`：
   - ModuleType 下拉框改为 API 动态加载
   - 去掉 TemplateCode 输入框和验证
   - TemplateName label 改为"模板描述"
   - 表单提交不再传 templateCode
4. i18n 新增翻译键

### 阶段四：编译验证
- 后端：`dotnet build`
- 前端：`npm run build`
- 数据库：`dotnet ef database update`

## 关键风险
1. **现有审批模板数据**：已有模板的 TemplateCode 是用户填写的，迁移后保留不变；新模板才走自动生成
2. **大小写统一后兼容性**：SQL Server 默认不区分大小写，所以 `"QUOTATION"` → `"Quotation"` 不会影响现有模板匹配；但代码中字符串比较（如 `Supports()`）需确保一致
3. **文件上传模块**：`FileRecord.ModuleType` 保持 lowercase，不影响现有文件查询
