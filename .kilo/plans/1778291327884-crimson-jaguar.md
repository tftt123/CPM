# 实际节拍维护功能设计

## 需求来源
用户在"工艺路线汇总"表格中需要增加"实际节拍"列，该值可能随时间多次变更，允许手工添加多条记录。

## 数据库设计

### 新增实体：PmProjectTraceStepActualCycleTime
```csharp
[Table("PmProjectTraceStepActualCycleTime")]
public class PmProjectTraceStepActualCycleTime
{
    [Key]
    public long Id { get; set; }
    
    public long ProjectTraceStepId { get; set; }
    
    /// <summary>记录日期</summary>
    public DateTime RecordDate { get; set; }
    
    /// <summary>实际节拍(秒)</summary>
    [Column(TypeName = "decimal(18,4)")]
    public decimal? ActualCycleTime { get; set; }
    
    /// <summary>备注</summary>
    public string? Remarks { get; set; }
    
    public DateTime CreatedAt { get; set; } = DateTime.Now;
    public DateTime UpdatedAt { get; set; } = DateTime.Now;
    
    [ForeignKey("ProjectTraceStepId")]
    public PmProjectTraceStep? Step { get; set; }
}
```

### DbContext 注册
在 `CpmDbContext` 中新增：
```csharp
public DbSet<PmProjectTraceStepActualCycleTime> StepActualCycleTimes => Set<PmProjectTraceStepActualCycleTime>();
```

### 迁移
生成并应用 EF Core 迁移 `AddStepActualCycleTime`。

## 后端 DTO 设计

### PmProjectTraceStepActualCycleTimeDto
```csharp
public class PmProjectTraceStepActualCycleTimeDto
{
    public long? Id { get; set; }
    public long? ProjectTraceStepId { get; set; }
    public DateTime RecordDate { get; set; }
    public decimal? ActualCycleTime { get; set; }
    public string? Remarks { get; set; }
}
```

### PmProjectTraceStepDto 更新
增加字段：
```csharp
public List<PmProjectTraceStepActualCycleTimeDto> ActualCycleTimes { get; set; } = new();
```

### PmProjectTraceService 更新
在 `GetDetailAsync`、`CreateAsync`、`UpdateAsync` 中处理 `ActualCycleTimes` 的加载和保存。

## 前端设计

### 1. API 接口更新
`PmProjectTraceStep` 接口增加：
```typescript
export interface PmProjectTraceStepActualCycleTime {
  id?: number
  recordDate: string
  actualCycleTime?: number
  remarks?: string
}
```

### 2. 工艺路线汇总表格改造
在现有表格的"预计耗时"列之后增加"实际节拍"列。

每个单元格显示：
- 如果该工序有实际节拍记录，显示最新一条的值
- 点击单元格展开一个弹窗（或行内展开），显示所有历史记录

### 3. 实际节拍编辑弹窗
弹窗标题："实际节拍维护 - {processName}"

内容：
```
+------------------------------------------+
|  日期        |  实际节拍(Sec)  |  备注   |  操作  |
|  2025-12-29  |  0.01          |         |  删除  |
|  2026-01-05  |  0.02          | 调机后  |  删除  |
|  [+ 添加]                                  |
+------------------------------------------+
```

- 每行可编辑日期、实际节拍、备注
- "+ 添加"按钮新增一行空白记录
- 删除按钮移除该行
- 保存时提交所有记录

### 4. 行内展开方案（替代弹窗）
在 Element Plus 表格中使用 `expand-row-keys` 实现行展开：
- 点击"实际节拍"列的单元格，展开该行下方区域
- 展开区域显示一个小表格（3列：日期、实际节拍、备注），带添加/删除按钮

## 实施步骤

1. **数据库**
   - 创建实体 `PmProjectTraceStepActualCycleTime`
   - 更新 `CpmDbContext`
   - 生成并应用迁移

2. **后端 DTO**
   - 新增 `PmProjectTraceStepActualCycleTimeDto`
   - 更新 `PmProjectTraceStepDto` 增加 `ActualCycleTimes` 列表
   - 更新 `PmProjectTraceCreateRequest` / `PmProjectTraceUpdateRequest`

3. **后端 Service**
   - `GetDetailAsync`：Include `Steps.ActualCycleTimes`
   - `CreateAsync`：保存 `ActualCycleTimes`
   - `UpdateAsync`：同步更新 `ActualCycleTimes`（删除旧记录，插入新记录）

4. **前端 API 类型**
   - 更新 `PmProjectTraceStep` 接口

5. **前端页面**
   - 工艺路线汇总表格增加"实际节拍"列
   - 实现弹窗/行展开编辑组件

6. **编译验证**
   - 后端编译
   - 前端编译

## 备注
- 由于 `PmProjectTraceStep` 在更新时采用"全量替换"策略（先删除旧 Steps 再插入新 Steps），实际节拍记录需要跟随 Step 的替换逻辑一起处理
- 在 `UpdateAsync` 中，保存新的 Step 后，需要将 `ActualCycleTimes` 关联到新的 StepId 再保存
